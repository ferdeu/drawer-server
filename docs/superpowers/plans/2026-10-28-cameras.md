# Cameras in the Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A home-only Cameras card in the status panel: stills that refresh every ~2.5 s, tap for a live full-screen view, set up by a new optional step 11.

> Note: this is the plan as written before building. In the final version go2rtc listens only on
> 127.0.0.1 (API 1984, RTSP 8554) and the panel passes live video through (`/live/ws`), home only.
> See `scripts/11-cameras.sh` and `termux/panel/cameras.py`.

**Architecture:** go2rtc (pinned binary, checksum-verified) pulls each camera once and serves live video to browsers over MSE on port 1984, plus RTSP on 127.0.0.1 for local use. The panel gets a small module, `termux/panel/cameras.py`, that starts one keyframe-only ffmpeg per camera on demand (reading from go2rtc's local RTSP) and stops it when nobody asks. The page shows the stills and opens go2rtc's `<video-stream>` player for live view.

**Tech Stack:** Bash (Git Bash on the PC), Python 3 standard library (Termux), go2rtc 1.9.15, Termux ffmpeg, vanilla JS in the panel page.

**Spec:** `docs/superpowers/specs/2026-10-28-cameras-design.md`

## Global Constraints

- go2rtc `v1.9.15`, asset `go2rtc_linux_arm64`, SHA-256 `af416f22b21a24ab83b8d78642190b4932ae695b4e386853f11d1b0319781763`; refuse to install on mismatch.
- Camera codes never reach the browser, page source, logs, repo or any command line; pass them over stdin, files with `umask 077`.
- `.env`: `PANEL_CAMERAS="Name=IP:CODE,..."`; optional `CAMERA_USER` (default `admin`), `CAMERA_MAIN_PATH` (default `/ch1/main/av_stream`), `CAMERA_SUB_PATH` (default `/ch1/sub/av_stream`). Port 554.
- go2rtc streams: `camN` = sub, `camN_hd` = main, N from 1 in `.env` order. API on `:1984`, RTSP on `127.0.0.1:8554`, WebRTC off, `api.allow_paths` limited to what the live view needs.
- Stills: `ffmpeg -nostdin -loglevel error -skip_frame nokey -rtsp_transport tcp -i rtsp://127.0.0.1:8554/camN -fps_mode passthrough -q:v 5 -update 1 -y <file>.jpg`; stop after 30 s without requests; page refreshes every 2500 ms only while visible.
- Home = request from a private address and not 100.64.0.0/10. Away: card says home only (showing the Wi-Fi address), `/api/camera/*` returns 403.
- Live: main stream; fall back to sub after decode error or 5 s without playing. One live video at a time.
- No login anywhere (owner's decision). Path A rules: nothing that erases, unlocks, flashes.
- Do NOT use go2rtc's `/api/frame.jpeg` or `exec:` sources (SIGSYS crash on Android).
- All repo text in English; panel texts in `en` and `es`.

## Review Focus

- A camera offline or go2rtc down: stills return "no image", the page and other cards keep working, ffmpeg isn't restarted more than once every 10 s.
- Leftover ffmpeg processes (panel restarted, ffmpeg hung): the panel kills its own stale ffmpeg at start and kills whole process groups on stop (the panel once left 1921 hung `termux-api` processes).
- Several tabs/devices asking for the same camera at once: exactly one ffmpeg per camera.
- A stale still (ffmpeg alive but stuck): an image older than 15 s counts as no image.
- Bad paths like `/api/camera/0.jpg`, `/api/camera/9.jpg`, `/api/camera/../x`: 404, no file read outside the stills folder.

### Task 1: Stills and home check module

**Files:**
- Create: `termux/panel/cameras.py`
- Test: `tests/test_cameras.py` (runs on the PC: `python -m unittest discover -s tests -v`)

**Interfaces:**
- Produces:
  - `load_names(path: Path) -> list[str]` — one name per non-empty line; missing file → `[]`.
  - `is_home(ip: str) -> bool`
  - `class Stills(names_count: int, folder: Path, url_for: Callable[[int], str] = default_url, idle_s: float = 30, stale_s: float = 15, retry_s: float = 10, cmd: Callable[[str, Path], list[str]] = ffmpeg_cmd)`
    - `get(n: int) -> bytes | None` — n is 1-based; raises `IndexError` out of range; starts ffmpeg for n if not running (respecting `retry_s`), records the request time, returns the JPEG if newer than `stale_s`, else `None`.
    - `reap() -> None` — stops processes idle longer than `idle_s` (kill the process group).
    - `stop_all() -> None`
    - `start_reaper() -> None` — daemon thread calling `reap()` every 5 s.
  - `default_url(n) -> "rtsp://127.0.0.1:8554/cam{n}"`, `ffmpeg_cmd(url, out) -> list[str]` (the exact command in Global Constraints).
  - `kill_leftovers(folder: Path) -> None` — kills ffmpeg processes whose command line contains `str(folder)`.

**Interfaces:**
- Consumes: Task 1 `load_names`, `is_home`, `Stills`, `kill_leftovers`.
- Produces:
  - Names file `~/.config/drawer-server/cameras` (written by Task 3). If it has names, the panel creates `Stills(len(names), DATA / "cams")`, calls `kill_leftovers` and `start_reaper()`.
  - `GET /api/camera/<n>.jpg` → 200 `image/jpeg` + `Cache-Control: no-store`; 204 when `get()` is `None`; 403 when not `is_home(self.client_address[0])`; 404 for anything not matching `^/api/camera/([1-9][0-9]?)\.jpg(\?.*)?$` or out of range.
  - `/api/status` gains `"cameras": {"names": [...], "port": 1984, "home": bool}` (`None` when no cameras) — `home` from the requesting address, so `status()` takes the client IP.
  - Services list gains `{"name": "Cameras", "ok": <go2rtc alive>}` when the names file exists; alive = `pid_alive(HOME / ".cache" / "go2rtc.pid")`. Friendly names: en "Cameras", es "Cámaras".
  - Port override: env `GO2RTC_PORT`, default `1984`.
