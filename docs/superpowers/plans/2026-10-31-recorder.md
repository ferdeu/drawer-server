# Camera Recorder and Disk Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional step 12 that records motion clips from the step 11 cameras (seconds before to
seconds after, HD copied as is), shows them in the panel at home, warns about cameras that look
obstructed, and adds a disk budget to the panel's 💾 card.

**Architecture:** A separate process, `recorder.py`, runs two ffmpeg per camera against go2rtc on
127.0.0.1. One decodes the small stream into gray 320×180 frames for motion detection (and writes the
panel's still as a second output). The other copies the HD stream as fragmented MP4 into an
in-memory ring that becomes a clip on motion. Clips are remuxed into `~/recordings/<camera>/<day>/`.
A JSON state file tells the panel what is happening. The panel lists and serves the clips (home only,
HTTP Range), shows warnings, and shows the disk split with optional Syncthing pausing.

**Tech Stack:** Python 3 standard library on Termux (3.14 on the server), Termux ffmpeg/ffprobe,
Bash (Git Bash on the PC), vanilla JS in the panel page.

**Spec:** `docs/superpowers/specs/2026-10-31-recorder-design.md` (approved by the owner 2026-10-31).
Read it first: this plan holds the decisions it left open, not its reasons.

**Server changed 2026-11-02:** Motorola Edge 40 (was the Moto G24 Power). Reviewed again on it: the
plan's commands work unchanged with its ffmpeg 9.0.2, the camera tests pass (`bash tests/run-on-phone.sh`,
32 OK), and the spec has the new measurements side by side with the old ones. Expected numbers below
are the Edge 40's.

## Global Constraints

- Standard library only: no pip packages, no OpenCV, no numpy. Code is deployed to `~/panel/` on the phone.
- Cameras are read only through go2rtc: `rtsp://127.0.0.1:8554/camN` (sub) and `camN_hd` (main), N from 1
  in the order of `~/.config/drawer-server/cameras`. No camera address or code in any command line,
  log, state file, test or page.
- Every ffmpeg runs in its own process group (`start_new_session=True`). To stop one: close its stdout
  first, then kill the group (an ffmpeg writing to a pipe nobody reads hangs on its trailer).
- Every recorder ffmpeg carries `-user_agent drawer-recorder` (an RTSP input option) so leftovers can be
  found with `pkill -f -- '-user_agent drawer-recorder'`.
- Paths: clips `~/recordings/<folder>/<YYYY-MM-DD>/`; state `~/.cache/drawer-server/recorder.json`;
  recorder stills `~/.cache/drawer-server/recorder-stills/camN.jpg`; log `~/.cache/drawer-server/recorder.log`
  (rotated at 1 MB, one old copy `recorder.log.1`); crash output `~/.cache/drawer-server/recorder.crash`;
  pid `~/panel/recorder.pid`; boot script `~/.termux/boot/70-recorder.sh`.
- Settings files (key=value lines, re-read every 30 s, clamped on read): `~/.config/drawer-server/recorder`
  (step 12), `~/.config/drawer-server/disk` and `~/.config/drawer-server/panel-recordings` (step 8).
- Defaults, verbatim from the spec: `RECORDER` empty = off; `RECORD_CAMERAS` all; `RECORD_BEFORE` 5;
  `RECORD_AFTER` 10; `RECORD_SENSITIVITY` 5; `RECORD_CHECK` `fast`; `RECORD_OBSTRUCTED` `keep`;
  `PANEL_RECORDINGS` shown; `DISK_RECORDINGS_GB` 10% of the disk; `DISK_BACKUP_GB` none;
  `DISK_BACKUP_PAUSE` no; `DISK_KEEP_FREE_GB` 5. GB = 10^9 bytes (the panel already uses that).
- Clamps (my call): before 0–30, after 2–60, sensitivity 1–10, keep-free at least 1 GB,
  recordings share 1 GB to the disk size.
- Deleting: only regular files matching the recorder's own name patterns, inside
  `~/recordings/<folder>/<day>/`, never through a symlink. Nothing else, ever.
- Every recordings route is home only (`is_home`) and `same_site`; `PANEL_RECORDINGS=no` makes them 404.
- Nothing about recordings loads until its section is opened. Panel texts in `en` and `es`; works at 390 px.
- Tests use made-up frames and ffmpeg's test pattern only, never real camera images. They run on the
  phone: `bash tests/run-on-phone.sh` (Task 1 adds `-k <name>` to run one class).
- All repo text in English. Path A: nothing unlocks, wipes or roots.
- No commits during the tasks: the owner commits only when asked. Task 12 runs `path-a-reviewer` and asks.
- The owner's server ends with the recorder off (`RECORDER` empty), unless the owner says otherwise.

## Review Focus

- **go2rtc restarted (step 11 re-run) or a camera rebooting in the middle of a clip**: the open clip ends at
  its last whole fragment and still plays; the next ffmpeg session starts a fresh header; nothing mixes
  the two sessions. Test: Task 4 `test_real_stream_two_sessions`.
- **Power cut or `kill -9` while recording**: on start, leftover `.part` files become playable clips (or are
  removed if unreadable), and leftover recorder ffmpeg are killed. Tests: Task 4 `test_recover_cut_part`,
  Task 5 `test_leftover_pattern`.
- **A clip that crosses midnight**: it stays in the day folder of its start and lists normally. Test:
  Task 3 `test_part_day_is_start_day`.
- **A camera renamed or removed in step 11 while the recorder runs**: its worker stops, its old clips stay
  listed under the old name and keep counting against the cap. Tests: Task 5 `test_camera_removed`,
  Task 3 `test_old_camera_folder_listed`.
- **The disk filling from something else** (photo backup growing): the free-space floor deletes oldest clips,
  then stops new clips and the panel says so; no other file is touched. Tests: Task 3 `test_floor`,
  Task 7 `test_status_disk_full`.

### Task 2: Motion detection

**Files:**
- Create: `termux/panel/motion.py`
- Create: `tests/test_motion.py`

**Interfaces:**
- Produces:
  - `W, H = 320, 180` (frame size; frames are `bytes` of length `W * H`, one gray byte per pixel).
  - `SENSITIVITY: dict[int, tuple[int, float]]` = levels and % of the image, starting values to tune on
    real footage: `{1: (40, 3.0), 2: (36, 2.0), 3: (32, 1.3), 4: (28, 0.8), 5: (25, 0.5), 6: (22, 0.35), 7: (19, 0.25), 8: (16, 0.18), 9: (13, 0.12), 10: (10, 0.08)}`.
  - `LIGHTING_SHARE = 0.6`: more than this share changed in one look = lighting change, not motion.
  - `changed_share(a: bytes, b: bytes, levels: int) -> float`: share (0–1) of pixels that changed.
    Exact rule: a change of `levels` or more always counts; a change of `levels // 2` or less never does.
  - `class Detector(sensitivity: int, looks_needed: int)`; attributes `sensitivity`, `looks_needed`
    can be changed between looks. `look(frame: bytes) -> bool`: True when this look and the
    `looks_needed - 1` before it all saw motion. First frame → False. Lighting change → False, the
    counter resets, the new frame becomes the reference.
  - `brightness(frame: bytes) -> tuple[float, float]`: mean and standard deviation of every 16th pixel.
  - `FLAT_SPREAD = 6`, `DARK_MEAN = 10` (starting values).
  - `class Obstruction(window_s: float = 600, on_share: float = 0.5, off_share: float = 0.25, flat_s: float = 60)`;
    `update(now: float, motion: bool, frame: bytes) -> str | None` returns `None`, `"moving"` or `"flat"`;
    `reset() -> None`.
- Fast mode uses `Detector(s, looks_needed=2)`, light mode `looks_needed=1` (my call: two looks in a row
  skips one-frame noise at two looks a second).

- [ ] **Step 3: Implement `changed_share`** with two shifted quantizations, so all the per-pixel work runs
  in C (measured 1.85 ms per look on the G24 and 1.08 ms on the Edge 40, vs 15 and 7.6 ms for a Python loop). Cache the two tables per
  `levels`, and the reference frame's quantized copies in `Detector`:

```python
NONZERO = bytes([0] + [1] * 255)

def _tables(levels):
    return (bytes(v // levels for v in range(256)),
            bytes(min(255, (v + levels // 2) // levels) for v in range(256)))

def _differs(qa, qb, n):  # 1 where the bucket changed, else 0
    x = int.from_bytes(qa) ^ int.from_bytes(qb)
    return int.from_bytes(x.to_bytes(n).translate(NONZERO))

def changed_share(a, b, levels):
    q1, q2 = _tables(levels)
    n = len(a)
    both = _differs(a.translate(q1), b.translate(q1), n) & _differs(a.translate(q2), b.translate(q2), n)
    return both.to_bytes(n).count(1) / n
```

- [ ] **Step 4: Implement `Detector`, `brightness`, `Obstruction`.** Obstruction keeps a deque of
  `(time, motion)` for the last `window_s`, judges "moving" only once `window_s` has passed since it
  started or was reset, turns on above `on_share`, off under `off_share`. "Flat" = spread < `FLAT_SPREAD` or mean < `DARK_MEAN` for
  `flat_s` without a break; it clears after `flat_s` of normal frames. Flat wins when both apply.

### Task 4: Fragments to clips

**Files:**
- Create: `termux/panel/clipmaker.py`
- Create: `tests/test_clipmaker.py`

**Interfaces:**
- Consumes: `ClipStore` from Task 3 (`new_part`, `remux_path`, `final_paths`, `parts`, `discard`).
- Produces:
  - `read_box(read: Callable[[int], bytes]) -> tuple[str, bytes] | None`: one top-level box (type, the
    whole box including its header). Size field 1 → 64-bit size follows. End of stream or a short read →
    `None`. Size 0 or under the header length → `ValueError`.
  - `pump(read, maker: "ClipMaker", clock: Callable[[], float] = time.time) -> None`: reads boxes until
    `None`; `ftyp`, then `moov` → `maker.header(ftyp + moov, clock())`; `moof` held; the next `mdat` →
    `maker.fragment(moof + mdat, clock())`; other boxes ignored.
  - `class ClipMaker(new_part: Callable[[float], Path], finished: Callable[[Path, float, float], None], before_s: float, after_s: float, split_s: float = 300, ring_max_bytes: int = 8_000_000)`.
    Thread-safe (one lock). `before_s`/`after_s` can change at any time.
    - `header(data: bytes, now: float)`: a new ffmpeg session: ends an open clip, empties the ring.
    - `fragment(data: bytes, now: float)`: a fragment covering (previous fragment's or header's time, now].
    - `motion(now: float)`: allowed motion was seen (the caller already applied pause and disk rules).
    - `stop(finish: bool = True)`: ends an open clip; `finish=False` closes the `.part` without calling
      `finished` (shutdown: recovered on next start).
    - `recording -> bool` (property).
    - `finished(part, length_s, thumb_at_s)` is called after the part is closed; `length_s` = end of last
      fragment − start of first; `thumb_at_s` = first motion − clip start, at least 0.
  - `remux(part: Path, out: Path) -> bool`, `thumbnail(clip: Path, at_s: float, out: Path) -> bool`,
    `duration(path: Path) -> float | None` (ffprobe), each with a 120 s timeout.
  - `finish(store: ClipStore, part: Path, length_s: float, thumb_at_s: float) -> Path | None`: remux to
    `remux_path`, rename to the final `.mp4`, make the thumbnail, delete the part; if the remux fails the
    part is discarded and `None` returned.
  - `recover(store: ClipStore) -> int`: every leftover part → `finish` with length from `duration` of the
    part (unreadable → discarded) and thumbnail at 0; leftover `.remux.mp4` discarded; returns clips saved.
- Ring and clip rules (my call; they implement the spec's "5 to 9 s" and "first boundary after"):
  - The ring keeps fragments whose end > `now − before_s − 15` (15 s of slack for long keyframe gaps),
    then drops the oldest while over `ring_max_bytes`.
  - On `fragment` with motion pending and no clip: open `new_part(first_motion)`, write the header and every
    ring fragment whose end > `first_motion − before_s` (the new fragment included).
  - With a clip open, each fragment is appended and flushed; the clip ends after the first fragment whose end
    ≥ `last_motion + after_s`.
  - At `split_s` from the clip's start the clip ends after the current fragment; if motion is still within
    `after_s`, the next fragment opens a new clip with the header and that fragment only (no ring, no gap).
- Exact commands:

```python
REMUX = ["ffmpeg", "-nostdin", "-loglevel", "error", "-y", "-i", "{part}", "-c", "copy", "-tag:v", "hvc1",
         "-movflags", "+faststart", "-f", "mp4", "{out}"]
THUMB = ["ffmpeg", "-nostdin", "-loglevel", "error", "-y", "-ss", "{at:.1f}", "-i", "{clip}", "-frames:v", "1",
         "-vf", "scale=320:-2", "-q:v", "5", "{out}"]
PROBE = ["ffprobe", "-v", "error", "-show_entries", "format=duration", "-of", "csv=p=0", "{path}"]
```

- Keeping the remux (my call; the spec asked to avoid it if practical): the on-disk `.part` is what
  survives a power cut, and browsers need the `+faststart` file to show the length and seek, so each clip
  is written twice. That only matters for a camera that moves all the time, which the docs steer to `pause`.
